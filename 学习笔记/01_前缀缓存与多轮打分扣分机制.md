## 一、核心问题：为什么多轮对话不能“一看到关键词就换模型”？

在大模型真实生产中，模型切换存在巨大的**隐形成本**：
1. **KV Cache（前缀缓存）丢弃损耗**：用户已经聊了 5 轮，前 5 轮的历史 Token（例如 4000 字）已经在当前模型的显存里缓存好了。如果第 6 轮切换到新模型，新模型显存中没有这些缓存，必须对 4000 字重新跑一遍 Prefill（前缀计算），不仅首字延迟（TTFT）暴增 1~2 秒，而且要额外支付 4000 字的完整 Token 费用！
2. **抽风震荡（Ping-Pong Switching）**：如果规则太敏感，用户每说一句话就切一次模型，上下文在不同模型之间反复倒手，体验极差。

vLLM Semantic Router 创造性地通过一套**前缀缓存惩罚数学模型**完美解决了这个问题。

## 二、核心公式拆解（源码 1:1 对照）

### 1. 缓存扣分计算总公式
源码位于 `session_aware_scoring.go` 第 148 行：
```go
PrefixCachePenalty = PrefixCacheWeight 
                   * ContinuationMass 
                   * sessionCacheWarmth(session, idleExpired) 
                   * cacheCostMultiplier(current, candidate)
```
整条公式由四个核心因子相乘而成：

#### 因子 1：`ContinuationMass`（历史沉淀质量，0.0 ~ 1.0）
源码第 320 行 `sessionContinuationMass`：
```go
contextTokens := math.Max(float64(session.ContextTokens), 1)
reuseRatio := clampF(float64(session.HistoryTokens)/contextTokens, 0, 1)   // 历史复用比例 (权重 45%)
historyMass := clampF(float64(session.HistoryTokens)/8192.0, 0, 1)        // 绝对历史字数 (权重 35%, 8192字封顶)
turnDepth := clampF(float64(effectiveSessionTurns(session))/8.0, 0, 1)   // 轮次深度 (权重 20%, 8轮封顶)

ContinuationMass = 0.45 * reuseRatio + 0.35 * historyMass + 0.20 * turnDepth
```
- **白话解释**：
  - 刚开始第 1 句：历史为 0，`ContinuationMass = 0`，换模型完全零负担；
  - 聊了 8 轮、字数达到 8000 字：`ContinuationMass = 1.0`（满格）。历史包袱极重，坚决阻止轻易换模型！

#### 因子 2：`CacheWarmth`（显存缓存温度，0.0 ~ 1.0）
源码第 334 行 `sessionCacheWarmth`：
- **热态（Warm）**：上一句话刚回复完，显存中的 KV Cache 依然有效，温度 = 1.0；
- **冷态（idleExpired 超时降温）**：
  ```go
  if idleExpired {
      warmth *= 0.2 // 用户走开了十几分钟，显存缓存已被淘汰，温度打二折
  }
  ```
  - **白话解释**：如果用户隔了很久才发下一句，老模型的显存缓存早就没了，此时换到新模型就没有那么心疼，扣分自动打两折！

#### 因子 3：`CacheCostMultiplier`（价格成本放大器，1.0 ~ 3.0）
源码第 161 行：
- 比较老模型与新模型的定价（每 100 万 Token 的费用）。
- 涉及的模型越贵，丢弃缓存重新跑 Prefill 造成的真金白银损失越大，因此惩罚按比例放大（最高放大到 3 倍）。

#### 因子 4：`PrefixCacheWeight`（基础惩罚权重）
- 系统配置的全局基准权重，用来控制系统对缓存保护的整体敏感度。

## 三、留守奖励与频繁跳车惩罚

除了上面的缓存报废惩罚，vLLM 还配齐了两道防线：

1. **频繁跳车惩罚（`SwitchHistoryPenalty`，源码第 154 行）**：
   ```go
   SwitchHistoryPenalty = SwitchHistoryWeight * clampF(float64(session.MemorySwitchCount) / 8.0, 0, 1)
   ```
   - 会话内部记录了 `MemorySwitchCount`（历史换车次数）。
   - 如果 8 轮内已经换了 3~4 次，扣分成倍加重，物理杜绝模型神经质乱跳。

2. **工具调用锁定（`ToolLoopStayBias`，源码第 71 行）**：
   - 如果机器人正在循环调用外部工具（Function Calling），老模型直接享受超高加分，禁止任何模型切换，防止工具执行上下文丢失。

## 四、最终裁决门禁（Model Switch Gate）

源码 `model_switch_gate.go` 第 246 行：
```go
NetSwitchAdvantage = switchBenefit - HandoffPenalty - CacheWarmthPenalty
WouldSwitch = NetSwitchAdvantage > MinSwitchAdvantage
```
- 只有当新模型的**能力提升（QualityGap）**，能够彻底盖过**换乘开销（Handoff）+ 缓存报废损失（CacheWarmthPenalty）+ 门槛值**时，才允许换模型！
- 这就是工业级多模型调度“既聪明升舱、又省钱防抖”的真相！
