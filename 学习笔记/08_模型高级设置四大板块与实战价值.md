## 一、概述：“高级设置”到底在配置什么？

在点击“OpenAI 兼容”录入模型时，折叠的【高级设置（Advanced settings）】并不是花哨的摆设，它是**大模型路由调度大脑做决策时的全部“身份证”和“体检表”**。

## 二、四大板块深度解剖（源码 1:1 对照）

### 板块 1：身份标识 (Identity)
用来给模型打标签，避免多环境混淆：
1. **`Name prefix`（名称前缀）**：比如填 `prod-` 或 `mini-`，导入多个模型时自动加前缀区分（如 `mini-deepseek-16b`）；
2. **`Reasoning family`（推理家族）**：指定该模型的思考协议（如 `qwen3`、`openai` 或留空）；
3. **`Description`（描述）**：写明这台模型最擅长做什么（如“本地 16B 极速代码模型”）。

---

### 板块 2：路由元数据 (Routing Metadata) —— ★ 对我们最有用！
这块是自动选型引擎最需要的核心特征：
1. **`Context window`（上下文窗口上限，如 131072 或 32768）**：
   - **神级价值（硬拦截）**：如果用户扔了一篇 5 万字的长论文，系统一查该模型窗口只有 32k，**在派单前直接一票否决排除它**，彻底杜绝发给模型后报“Context Length Exceeded（上下文超长）”的恶性崩溃！
2. **`Parameter size`（模型参数量，如 16B、32B、70B）**：
   - 帮助系统直观判定是“轻量端”还是“重型端”；
3. **`Capabilities`（能力逗号列表）**：
   - 标注：`reasoning, coding, tools, vision`（支持思考、写代码、调外部工具、识图）；
   - 比如用户上传了图片，系统只会在带 `vision` 的模型中挑选；
4. **`Modality`（模态类型）**：
   - 文本（`ar`）、多模态全能（`omni`）、图像生成（`diffusion`）。

---

### 板块 3：价格计费 (Pricing) —— ★ 自动算分扣分的基准！
每 100 万 Token 的费用（美元/人民币）：
1. **`Input cost`**：输入 Token 价格；
2. **`Output cost`**：输出 Token 价格；
3. **`Cache read cost`**：前缀缓存命中读取价（通常只有输入价的 10%~20%）；
4. **`Cache write cost`**：缓存写入价；
- **业务价值**：在前面的打分公式中，系统就是用这里的价格来算**成本惩罚分（Cost Penalty）**和**丢弃缓存放大器（CacheCostMultiplier）**的！填上价格，系统才能帮你自动省钱。

---

### 板块 4：传输与负载均衡 (Delivery)
模型后端的网络级可靠性配置：
1. **`Load balancing`（多节点负载均衡）**：
   - `ROUND_ROBIN`（简单轮询）；
   - `LEAST_REQUEST`（最少请求数，谁空闲派给谁，**自建多机器首选**）；
   - `RING_HASH`（一致性哈希，相同前缀打到同一台机器，**利于显存缓存复用**）；
2. **`Max retries`（最大重试次数，0~5 次）**；
3. **`Retry conditions`（重试条件）**：如遇到 `5xx` 报错或连接断开才重试；
4. **`Health check path`（健康体检路由）**：默认 `/health`，定期测活。

## 三、对我们小毛驴架构的“取舍”建议（哪些最有用？）

### 必留的核心实用项（极高价值）：
1. **`Context window`（上下文窗口大小）**：必留！长文本直接熔断，防止打爆小模型；
2. **`Capabilities`（能力标签：tools / vision / coding）**：必留！有图派识图模型，有工具派工具模型；
3. **`Pricing`（单价）**：必留！哪怕自建模型写 0 元，商业模型填真实价格，系统才能算省钱账；
4. **`Reasoning family`（推理家族）**：必留！抹平思考协议；
5. **`Health check`（测速探针）**：必留！绿灯红灯一目了然。

### 可以先精简省略的复杂项（原型期免折腾）：
- 复杂的重试策略（`Retry conditions`）和多种高阶哈希算法（`MAGLEV`），我们本地机器少，直接用简单轮询或最少请求即可。
