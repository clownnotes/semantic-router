## 一、概述：仪表盘上的“68 信号”与“27 决定”

在系统顶部仪表盘中，有两个并排的核心指标：
- **`68 信号 (Signals)`**
- **`27 决定 (Decisions)`**

它们不是杂乱的参数，而是整套智能路由调度引擎的核心灵魂。源码 `DashboardMiniFlowDiagram.tsx` 用极其优雅的流程图给出了唯一真相定义：

$$\text{SIGNALS (雷达传感器)} \longrightarrow \text{DECISIONS (裁决法官)} \longrightarrow \text{MODELS (落地模型)}$$

## 二、信号 (Signals) 的本质：系统的“眼睛与耳朵”

### 1. 它是做什么的？
当用户的 Prompt（或者请求上下文）发过来时，系统第一步绝不是立刻去挑选模型，而是先用一组**探测器（Signals）**进行全方位扫描，把输入特征“抽离”成标准标签。

### 2. 源码支持的 24 种经典探测器（最实用的几种）：
1. **关键词探测 (`keyword`)**：抓取敏感词、代码专有名词、业务品牌词；
2. **向量语义探测 (`embedding`)**：用微型轻量 Embedding 模型算语义相似度，识别用户真实意图；
3. **模态探测 (`modality` / `input_modality`)**：检测请求是否携带图片、音频、文件附件；
4. **上下文长度探测 (`context`)**：检查上下文 Token 数（例如：`< 4k`、`4k~32k`、`> 32k`）；
5. **复杂度探测 (`complexity`)**：判定任务是简单问答、中等创作，还是深度推理；
6. **用户负反馈探测 (`user_feedback` / `reask`)**：捕获用户上一轮的“点踩”、报错重试或反问。

> **核心价值**：信号只负责“检测”，不决定派发给谁。这叫**关注点分离**。

## 三、决定 (Decisions) 的本质：系统的“裁决法官”

### 1. 它是做什么的？
`Decisions` 就是一组带**优先级（Priority）**的业务流转规则。它根据前面提取出的各种信号，进行逻辑组合判断（`AND` / `OR` / `NOT`），然后圈定候选模型并指定挑选算法。

### 2. 源码中一条标准的 Decision 包含 4 个核心要素：
```yaml
decisions:
  - name: "代码与深度推理路由"
    priority: 100               # 优先级（数字越大越先判定）
    rules:                      # IF：如果满足哪些信号
      operator: OR
      conditions:
        - type: keyword
          name: coding_keywords # 命中代码关键词信号
        - type: complexity
          name: hard_reasoning  # 或命中高难度推理信号
    modelRefs:                  # THEN：圈定哪几个模型
      - model: deepseek-r1
      - model: claude-3-7-sonnet
      - model: qwen-max
    algorithm:                  # HOW：用什么算法在圈定模型里挑
      type: auto                # 自动打分（算分选最高），或最便宜、或最少并发
```

## 四、对 Nextdoor / XiuLan 的经验吸取与取舍建议

### 1. 为什么“信号”与“决定”必须解耦？
- **传统劣质设计（反模式）**：在每一个业务 Handler 或路由判断里硬写 `if strings.Contains(prompt, "代码") { ... }`。只要业务一变，代码改得一塌糊涂，这就是典型的打补丁面条代码。
- **解耦后的现代设计（优雅模式）**：
  - **下沉探测器**：后端独立出轻量特征提取层（检查图片、查 Token 长度、查关键词、查用户吐槽）；
  - **规则配置化**：运营或管理员在后台只需要勾选组合：“只要命中【长文本】+【需要写代码】，就分流到【DeepSeek-Coder】”。

### 2. 结合咱们已有基建（已有重试与健康探针）的极简落地路线：
- 咱们系统已经有了 **重试（Retry）** 和 **健康探针（Health Check）**，这极大减轻了工作量！
- 咱们目前只需要吸纳最核心的 **3 个高频信号**：
  1. **图片/附件模态信号**（带图直接排他过滤掉纯文本模型）；
  2. **上下文超长信号**（长文本一票否决小窗口模型）；
  3. **关键词/场景信号**（代码、翻译、闲聊等场景分类）。
- 并在后台提供一套极简的 **决定规则卡片（Decisions）**：`IF 命中信号组合 -> 派发给对应模型组`。
