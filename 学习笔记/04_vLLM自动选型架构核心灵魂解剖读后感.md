## 序言：为什么我们要花大力气深扒它？

在过去很多人的直觉里，“模型自动选型”大概就是：
> “写几条 `if (提问带写代码) { 调代码大模型 } else { 调通用小模型 }`。”

但在真实高并发、长对话的业务实战中，这种简陋的硬切有三大**致命死穴**：
1. **账单爆表**：用户随口打了个招呼，系统无脑调了最贵的大模型；
2. **首字暴卡**：用户聊了 8 轮历史，第 9 轮突然换了个模型，导致新模型必须花几秒钟把前面几千字全部重算一遍（KV Cache 彻底报废）；
3. **神经质乱跳**：多轮会话中模型来回倒手，上一句是大模型，下一句又变成小模型，上下文频繁断层。

`vllm-semantic-router` 作为当前全球大模型基础设施中最活跃、最前沿的官方级开源项目，用一整套极其优雅的工程与数学架构，完美解决了这三大死穴。以下是我们这几天对照其源码深扒得出的核心灵魂总结。

---

## 灵魂一：四步级联漏斗流水线 (Pipeline)

系统处理任何一条请求，绝不搞一锅端，而是清晰分为四步：

```
用户提问 (Prompt)
       │
       ▼
【第 1 步：信号嗅探 (Signals Extraction)】（0 ~ 10ms 纯 CPU 并行计算）
├── 词法信号 (keywords): 0ms 硬词字典快速查表（包含 BM25、精准词）
├── 语义信号 (embeddings): 5~10ms 本地微型 BGE 模型算向量相似度
├── 复杂度信号 (complexity): 统计 Token 长度、是否带代码块、多轮上下文深度
└── 情绪与安全信号 (safety & user_feedback): 识别骂人违规、嗅探用户满意度
       │
       ▼
【第 2 步：决策仲裁阶梯 (Decisions Arbitration)】（优先级漏斗）
├── Priority 100: 【安全拦截】违规词一票否决
├── Priority 150: 【用户抱怨升舱】检测到用户说“错了”，立刻触发重思并派大模型
├── Priority 200: 【硬词直通】命中核心词直接短路，省去耗时向量计算
├── Priority 300: 【语义门槛】向量相似度 ≥ 0.85 命中深度规则，0.70~0.85 给出推荐
└── Priority 999: 【兜底兜网】全未命中走便宜默认小模型
       │
       ▼
【第 3 步：内联推理级别组装 (Inline Reasoning Level)】
└── 根据任务难度，动态给大模型指定“思考 Token 预算”（Low / Medium / High）
       │
       ▼
【第 4 步：最终分发 (Model Dispatch)】
└── 带着目标模型 ID 与思考参数发起真正的网络生成请求
```

## 灵魂二：前缀缓存（KV Cache）与换车扣分经济学

这是整个开源项目最具智慧的核心数学模型（源码 `pkg/selection/session_aware_scoring.go`）。

多轮聊天中，系统坚决**反对神经质乱换模型**，它把老模型与新模型放在天平上称重：

### 1. 留守老模型，给“三大奖励”
$$\text{老模型最终分} = \text{基础分} + \text{留守偏好(StayBias)} + \text{缓存命中奖励(PrefixCacheBenefit)} + \text{工具调用锁(ToolLoopStayBias)}$$
- **缓存命中奖励**：前几轮历史对话已经在老模型显存（KV Cache）里了，不用重新做 Prefill 计算，0 毫秒秒回，又省钱又顺畅，系统给它大加分！
- **工具调用锁**：正在调外部 API 或数据库时，死死锁住当前模型，绝不换车。

### 2. 想换到新模型，必须接受“严厉惩罚扣分”
$$\text{新模型最终分} = \text{基础分} + \text{能力差距} - \text{换乘代价} - \text{缓存报废扣分} - \text{频繁跳车惩罚} - \text{起步门槛}$$
- **历史包袱质量（ContinuationMass）**：聊天历史字数越多（8192 字封顶）、轮次越深，扣分越重；
- **显存温度冷却（CacheWarmth）**：刚聊完显存还是热的，惩罚打满；如果用户走开十几分钟才回，老缓存冷了，**惩罚自动打两折**，放宽换大模型的门槛；
- **频繁跳车惩罚（SwitchHistoryPenalty）**：8 轮内换车次数越多，扣分越狠，彻底杜绝模型乱跳。

### 3. 净胜优势裁决（NetSwitchAdvantage）
$$\text{净胜分} = \text{新模型得分} - \text{老模型得分}$$
只有当新模型的聪明程度**彻底碾压**了换乘和丢缓存的代价时，系统才批准换模型！否则坚决继续用老模型！

## 灵魂三：模型战力分绝不靠人工瞎拍脑门

系统怎么知道“模型 A 比模型 B 在写代码上聪明几分”？源码证明绝非人工主观定死：
1. **支柱 1：权威 Elo 竞技场天梯（RouteLLM & LMSYS Chatbot Arena）**：
   引入加州大学伯克利分校等国际公认的盲测天梯分，用 Bradley-Terry 概率公式算出客观胜率；
2. **支柱 2：真实流量日志回放推导（Replay Builder）**：
   在后台定期对真实用户的调用日志进行统计，计算各大模型在各任务下的实际置信度平均分之差；
3. **支柱 3：新模型冷启动配置兜底**：
   只有刚接进来的新私有模型才由人工填初始种子分，一旦运行，立刻被真实调用数据自动校正覆盖。

## 灵魂四：用户抱怨自动升舱（Implicit Feedback）

系统绝不每轮调一个大模型来打分评判（避免成本翻倍和多等 2 秒）。

而是靠轻量分类器嗅探用户在下一轮说的话：
- 当用户抱怨：“不对”、“算错了”、“重新写一个”；
- 0 毫秒抓到 `wrong_answer` 信号；
- **一箭双雕**：
  1. 记老模型一次败绩，降低战力分；
  2. 触发规则自动升舱，把问题转交给高级推理大模型重做，附带“请仔细复核重新思考”的提示词，用户感觉系统极其贴心和聪明！

---

## 灵魂五：SLO 门禁一票否决是“按业务决策定制”，而非全局一刀切

在算分之前，系统设立了体检生死门（SLO Ceilings）：
- **首字延迟门槛（MaxTTFTMs）**：太卡直接淘汰；
- **吐字卡顿门槛（MaxTPOTMs）**：吐字太慢直接淘汰；
- **单价预算上限（MaxCostPer1M）**：太贵直接淘汰；
- **并发排队熔断门槛（MaxInflight）**：排队爆满直接淘汰，防止压垮机器。

> **师弟敏锐指出的架构事实确认**：  
> 源码中 SLO 门禁是**配置在每个具体的 Decision 决策上**的！  
> - **面对用户的实时聊天路由**：配置严格的 TTFT/并发门禁，防止用户等太久、防止小机器被压崩；  
> - **后台异步跑批/离线文审/文档总结**：完全不设严苛延迟门禁，允许便宜、慢速的模型在后台慢慢排队跑，各取所需！

---

## 总结：对我们小毛驴后续开发的落地启示

我们的小毛驴模型数量有限（主要是自建轻量 16B 小模型 + 商业云端深度大模型），不需要照搬开源项目上千个模型的超复杂拓扑，而是**精准吸纳其三大精髓**：

1. **白盒硬词 0 毫秒嗅探直通**：高危领域命中硬词一票否决升深度；
2. **多轮对话前缀缓存留守偏好**：用户聊得正顺畅且字数很多时，除非遇到难题，坚决留在本地 16B 小模型，不丢缓存，省下巨额云端 Token；
3. **用户抱怨“错了”一键自动升舱**：只要用户提出质疑，自动唤醒深度推理模型重做，打造极致贴心的用户口碑！
