## 一、首先：整个“决定 (Decision)”到底是在干什么？

用五年级小学生都能懂的话讲：
**“决定”就是整个大模型调度系统里的【分诊台与派单专线】！**

- **信号 (Signals)** 是前面的“体检化验单”（化验出：带图、超长、商业类、写代码）；
- **决定 (Decision)** 拿这张化验单按规则判定：
  1. **能不能走这条专线？**（检查化验单是否符合门禁）；
  2. **派哪几位医生（模型）接单？**；
  3. **路上要装备什么外挂？**（悄悄注入人设、查缓存、压缩废话）。

## 二、场景拆解：为什么会有“静态业务 (static_business_route)”这个场景？

### 1. 现实中的业务痛点
很多企业管理、日常商务咨询、规章制度问答，**既不需要昂贵的 70B/R1 大模型去慢吞吞思考，也不允许乱选模型产生波动**。它们需要的是：“极速、便宜、答案规范、确定性极高的快速答复”。

### 2. 这个场景的定位
`static_business_route` 是系统为**日常标准商业咨询流量**打造的一条**“确定性直达快车道”**（Static fallback for standard business traffic）。

## 三、弹窗里的“配件”全解剖（它是怎么联合使用的？）

在“编辑决定”弹窗里，源码将参数清晰分成了 **四大板块配件**：

```
┌────────────────────────────────────────────────────────┐
│ 板块 1：Identity (身份工牌)                              │
│ • Name: static_business_route                          │
│ • Priority: 200 (优先级高，先过安检)                      │
│ • Tier: 2 (梯队)                                       │
│ • Description: 标准业务流量的确定性兜底快车道              │
├────────────────────────────────────────────────────────┤
│ 板块 2：Routing policy (门禁安检与候选车队)              │
│ • Rule Tree (安检门禁):                                │
│     IF 命中 [domain: business] 信号 (只放行商业类咨询)    │
│ • Model References (候选车队):                          │
│     派发给 [qwen3-8b]，并且 use_reasoning = false (关思考)│
├────────────────────────────────────────────────────────┤
│ 板块 3：Selection & runtime (选拔裁判与随身外挂)         │
│ • Algorithm (选拔算法): static (静态指定，无需复杂打分)   │
│ • Plugins (随身外挂插件链):                             │
│     ① shadow_dispatch: 5%流量偷跑32B新模型暗中考核        │
│     ② system_prompt: 悄悄塞入“资深商业顾问”专业人设      │
│     ③ response_cache: 一模一样的问题直接拿缓存秒回 0成本  │
│     ④ context_compression: 聊天太长自动压缩冗余工具内容   │
├────────────────────────────────────────────────────────┤
│ 板块 4：Output behavior (交单合同与军令状)               │
│ • Output Contract: 严格保持用户要求的格式，不要有多余废话│
└────────────────────────────────────────────────────────┘
```

## 四、它们是如何联合协同工作的？（完整时序）

1. **第 1 步（进门安检）**：用户发来一句“请帮我拟一份公司员工报销管理规范”。
2. **第 2 步（信号匹配）**：系统雷达捕获到 `domain: business` 信号，正好撞进 `static_business_route` 的 **Rule Tree**，门禁放行！
3. **第 3 步（组装外挂）**：系统在发给模型前，触发 **Plugins**：
   - 先查 **response_cache**（没命中）；
   - 再注入 **system_prompt**（自动贴上资深顾问人设）；
   - 顺便派发一个异步 **shadow_dispatch**（抽 5% 流量给后台 32B 新模型偷跑评估）。
4. **第 4 步（精准派单）**：根据 **Model References** 和 **static** 算法，不需要任何复杂算分，直接打到快准狠的 `qwen3-8b` 实例上，关掉思考，秒级吐出规范答案！
5. **第 5 步（交付用户）**：按照 **Output Contract** 规范清洗格式后，把结果呈现在用户面前。

## 五、对我们 Nextdoor / XiuLan 小毛驴的极简吸收启发

这个页面看起来参数极多，但核心本质非常精炼：
- **我们只需要保留最值钱的 3 个零件**：
  1. **规则安检（Rule Tree）**：绑定我们的场景标签（房产、闲聊、求助）；
  2. **派发车队（Model Refs）**：圈定派给本地 16B 还是 DeepSeek；
  3. **人设注入（System Prompt）**：顺手把该场景的提示词带上。
- 其他高级功能（如 5% 流量偷跑影子测试、上下文动态压缩），我们代码接口预留，后续需要时一键开启即可！
