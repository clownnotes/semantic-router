## 一、破案：为什么叫“现场表演”？（又一次搞笑机翻）

截图里表格表头的**“现场表演”**，是浏览器网页翻译闹出的又一个大笑话：
- **英文原词**：`Live`（组件名：`ConfigPageModelLiveVerification`）
- **正确专业中文**：**“在线探测 / 存活自检”**
- 浏览器翻译把 `Live` 误当成了电视直播、演唱会“现场表演（Live Show）”，其实它是一个**模型实时连通性体检探针**！

---

## 二、探针核心逻辑：“在线探测（Live Verification）”是干嘛的？

源码 `ConfigPageModelLiveVerification.tsx` 揭示了它的四个状态：

1. **灰点（Not checked，未检查）**：模型刚录入，还没做过连通性测试；
2. **黄点（Checking...，探测中）**：正在发送一条极简的真实测试请求；
3. **绿点（Live，在线可用）**：恭喜！网络通畅、API Key 有效、模型响应正常；
4. **红点（Unavailable，不可用）**：探测失败！并在旁边显示红字告警（如 Key 过期、超时、端点 404 等）。

### 设计意义与商业价值：
- 在传统系统里，很多模型配好了配置，但根本不知道它在后端到底能不能打通，直到线上用户报错了才发现；
- vLLM 在表格每一行右侧放了一个**刷新探测小按钮**，管理员随手一点，立刻向该模型发送一次真实探测，**秒级确认该模型是否健康**，不用去调复杂代码排错！

## 三、“23 个决定（Routing Use）”的设计逻辑与安全防线

截图表格第 4 列的“路由使用（Routing Use）”，标注着 `23个决定 (23 decisions)` 或 `未使用的 (Unused)`。

源码 `ConfigPageModelInventoryPanel.tsx` 第 127~142 行：
```tsx
const references = modelReferenceCounts.get(row.name) ?? 0
return references > 0 ? (
  <span className={styles.referenceBadge}>
    {references} {references === 1 ? 'decision' : 'decisions'}
  </span>
) : (
  <span className={styles.unusedLabel}>Unused</span>
)
```

### 设计意义：
1. **防止误删核心模型（防踩坑）**：
   - 很多后台管理员想清理废弃模型，但根本不敢删，因为不知道删了这个模型线上会崩哪些业务；
   - 系统实时反向统计：这个模型被 **23 条决策规则引用**！
   - 管理员一眼就能看出：这是核心模型，千万不能随便删！
2. **识别“僵尸模型”（降本省心）**：
   - 如果一个模型标注为 **`未使用的 (Unused)`**，说明全站没有任何一条规则派活给它，管理员可以放心地一键删除或停用它，清理显存空间。

## 四、对我们小毛驴后续界面的启示

在开发我们小毛驴的模型管理界面时，这两项设计体验极佳，可以直接吸收：
1. **给每个模型配一个“连通性测速探针”**：
   - 绿灯/红灯一目了然，带一个小刷新按钮，管理员配完 Key 点一下就测通，杜绝黑盒盲猜；
2. **显示“正在被几个场景/工作流使用”**：
   - 提示管理员该模型的依赖情况，避免删错破坏线上正在运行的工作流。
